# gsc-mcp — Google Search Console як локальний MCP

Прямий читальний доступ до Search Console з Claude: `sc-domain:example.com` і будь-яка
інша властивість, у яку впустили сервісний акаунт. Пишеться нічого — скоуп `webmasters.readonly`.

## Навіщо, якщо вже є `open-seo`

Конектор OpenSEO проксіює GSC, але звужує його: `type` має шість значень, немає ні URL
Inspection, ні мап сайту, ні довільних фільтрів. Цей сервер говорить із Google напряму.

## Інструменти

| Інструмент | Що віддає |
|---|---|
| `sites` | властивості, доступні сервісному акаунту, і рівень доступу |
| `performance` | Search Analytics: будь-які виміри, фільтри, тип пошуку, до 16 місяців + нерозрізані підсумки |
| `compare` | вікно проти попереднього такої ж довжини: дельти й список, що виросло/впало/зникло |
| `inspect_url` | стан індексації однієї сторінки, який канонікал вибрав Google, коли краулив |
| `sitemaps` | подані мапи сайту, помилки, попередження |
| `index_coverage` | обхід усього сайтмапу з вердиктом на кожен URL і зведенням по станах |

Ті самі інструменти доступні зі скрипта, без JSON-RPC:

```bash
uv run --script server.py --call compare '{"days":28}'
uv run --script server.py --check
```

## Requirements & integrations

| Інтеграція | Для чого | Обов'язково? | Авторизація / налаштування |
|---|---|---|---|
| Google Cloud проєкт `<gcp-project>` | вмикає Search Console API | так | API `searchconsole.googleapis.com` = Enabled |
| Сервісний акаунт `<service-account>@<gcp-project>.iam.gserviceaccount.com` | ідентичність запитів | так | JSON-ключ у `~/.config/gsc-mcp/service-account.json`, права 600; шлях змінюється через `GSC_CREDENTIALS` |
| Search Console → Користувачі | доступ до ДАНИХ (IAM його не дає) | так | додати пошту акаунта з дозволом **Повний**; без цього `sites` порожній, решта 403 |
| `uv` | запуск скрипта з PEP 723-залежностями | так | `uv`, залежності тягне сам |
| Властивість за замовчуванням | щоб не передавати `site` у кожен виклик | ні | `GSC_DEFAULT_SITE`, зараз `sc-domain:example.com` |

Реєстрація в Claude — user scope в `~/.claude.json`, ім'я `gsc`.

## Граблі

- **AI-режиму тут немає і не буде.** Звіт «Функції на основі генеративного ШІ» Google віддає
  лише в інтерфейсі: ні Search Analytics API, ні вивантаження в BigQuery його не містять.
  Тільки покази, без кліків, історія з 18.05.2026. Джерело для дашборда — ручний експорт
  (`linkedin-posts/scripts/import_gsc_ai.py`).
- **`indexed` у `sitemaps` завжди 0.** Поле застаріле, Google не заповнює його нікому. Читати
  його як «нічого не проіндексовано» — хибний висновок; правду дає `index_coverage`.
- **`inspect_url` нестабільний у підстані.** Той самий URL за два послідовні виклики може
  дати «Discovered – currently not indexed» і «URL is unknown to Google». Факт «не в індексі»
  надійний, конкретна стадія — ні. Не будувати на ній діагноз, не порівнювати прогони.
- **Останні 2–3 дні неповні** — тому вікно за замовчуванням закінчується на 3 дні тому.
- **Сума рядків < підсумку.** Google ховає низькочастотні запити; підсумки брати з `totals`,
  а не складати рядки.
- **403 = не запросили акаунт у властивість**, а не зламаний ключ. Ролі IAM тут ні до чого.
